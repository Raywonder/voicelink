Build 103 completes iOS room presence, server navigation, selected-server administration, and automatic room-media recovery.

What changed:
- Rejoining or reopening an already-connected room now re-announces the active room and current user to the app state, so the People list and audio controls no longer remain in a half-joined state.
- The Servers tab loads every configured iOS server in parallel instead of stopping after the first reachable server.
- Administration actions are checked against and opened for the server selected in the directory, rather than the previously preferred server.
- iOS now completes its room-join activation from the server acknowledgement, rather than waiting only for a later realtime event. The app records activation stages and makes acknowledgement failures retryable instead of silently leaving the room half-joined.
- Server owner/site blocks and individual servers open on their own screens instead of expandable sections.
- A selected server shows its owner, description, open/closed join state, guest policy, contact action, and Administration Settings when authorized.
- Rooms can display a compact, expandable media panel. Audio streams show a small status display; video appears only when the room source contains video.
- Room media autoplays after the server confirms the join. Dropped media retries automatically using the server administrator's attempt, delay, and cooldown policy; room users cannot override it.
- Audio Settings includes Media Playback Volume and lets Mute Room Output affect room audio only or room audio plus media.
- Room preview plays briefly without presenting a separate screen.
- Guest users can join a room and use basic microphone and output controls. Administrative actions remain server-authorized.
- Audio Settings adds a join preference: use the room default, always join muted, or always join unmuted.
- Mastodon-authenticated sessions refresh rooms after sign-in and do not silently downgrade a failed signed-in join to guest mode.
- Room transcript events continue into Live Transcripts when the server provides them.
- The beta can automatically send diagnostics on first launch and periodically while active; Settings also includes Send Diagnostics Report.
- VoiceLink server bot defaults prefer Codex/OpenClaw before local fallback models, with existing role boundaries preserved.
